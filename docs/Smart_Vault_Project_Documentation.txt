1. Product Overview
Smart Vault is an AI-powered family document and asset management system. It is designed to do more than store
files: it connects documents to real-life assets, identifies document types, extracts important details, tracks missing
documents and expiry dates, answers questions about stored information, and supports controlled emergency sharing.
The product lifecycle is: STORE → UNDERSTAND → ORGANIZE → TRACK → ALERT → SEARCH → SECURELY
SHARE.
What makes it different?
  Documents are organized around assets such as a vehicle, property, or family member.
  AI extracts details from uploaded documents, but users review and confirm the information before it is saved.
  The system compares uploaded documents with an asset-specific checklist.
  Expiry alerts and readiness indicators help users understand what needs attention.
  Natural-language search helps users ask questions about their own documents.
  Emergency nominee access follows explicit rules, waiting periods, owner veto, and audit logging.
 Important boundary: AI extraction is not official government authenticity verification. Smart Vault must not claim that a
document is genuine unless a real, authorized verification service is integrated.
2. Assets and Document Checklists
Users create an asset first and upload documents gradually. They do not need to provide every document when
creating the asset.
Supported asset types
  Vehicle: example — Honda City.
  Property: example — Flat 302.
  Person: example — Self or a family member.
  Other: for additional asset categories.
 
Example checklists
  Honda City — Vehicle: required: RC, Insurance, PUC, Driving License.
  Flat 302 — Property: required: Registry, Property Tax Receipt, Electricity Bill; optional: Rent Agreement.
  Self — Person: required: Aadhaar, PAN, Health Insurance; optional: Passport.
 The asset detail page should show required documents, uploaded documents, missing documents, and expiry status.
The checklist should update after a document is confirmed and saved.
3. AI Document Extraction Workflow
Each uploaded document follows a controlled workflow:
  Securely store the uploaded file after encryption.
  Identify the likely document type using AI.
  Extract fields such as document number, holder name, issue date, expiry date, issuer, and additional details.
  Show extracted values to the user for review and editing.
  Save the user-confirmed data and relevant metadata.
  Compare the document against the asset checklist.
  Update missing-document indicators, readiness, and expiry tracking.

AI_MOCK=true to use it.
Mock behavior

Required endpoints

  POST /auth/login — authenticate and return a token.
  GET /me — return the current authenticated user.
 All assets, documents, search results, nominees, and audit data must be scoped to the current user. The backend must
enforce this independently of frontend behavior.

9. Expiry Tracking and Renewal Links

  Expired: fewer than 0 days remaining.
  Urgent: 0–7 days remaining.

  Healthy: more than 30 days remaining.
 Use readable labels and text in addition to color, so status is not communicated by color alone.

10. Readiness Score
The readiness score is a weighted indicator intended to help users prioritize work. It is not a legal compliance certificate.
  50% — Completeness: required documents present divided by total required documents.
  30% — Expiry health: healthy documents divided by documents that have expiry dates.
  20% — Nominee setup: no nominee = 0 points; invited nominee = 10 points; active nominee = 20 points (out of the
 20-point contribution).
Return the overall score, category breakdown, next actions, estimated improvement, alerts, asset summary, and
missing-document counts.
Example next action: “Upload PUC for Honda City” with an estimated improvement such as +8 points. Improvement
values should be calculated from the actual score logic rather than hard-coded.
A document is considered healthy for the readiness calculation when it is not expired and has more than 30 days
remaining.
11. Natural-Language Search
Users should be able to ask questions such as “When does my car insurance expire?” The backend retrieves relevant
fields and text from the current user's documents and may use Gemini to formulate an answer.
  Only use facts available in the user's stored documents.
  Return sources with document_id, title, field, and value.
  If the requested information is missing, explicitly say it was not found.
  Do not invent answers or expose another user's documents.
 The mock search should support example queries about insurance expiry, missing documents for Flat 302, and PUC
expiry.
12. Emergency Nominee Access
The owner can add a trusted nominee. The nominee should not see protected documents while an access request is
pending.
Shareable documents
The default is_emergency_shareable value is true for Insurance, Health Insurance, Aadhaar, RC, and Registry.
The owner can change this setting for each document.
Access flow
  Nominee requests emergency access.
  A waiting period starts. Use ACCESS_WAIT_SECONDS=60 for the demo; the intended production concept is a
 longer period, such as 7 days.
 The owner sees a countdown and can veto the request.
  Before approval, the nominee sees no protected documents.
  After the waiting period, a pending request can be lazily resolved to approved when read, unless it was vetoed.
  After approval, the nominee sees only documents marked as emergency-shareable.
  Nominee access is read-only: no editing, deleting, or owner-only controls.

24. How to Explain the Innovation to Judges
Smart Vault is not just a digital locker. It is a family document autopilot. A traditional file store expects people to know
what to upload, remember expiry dates, and manually search files. Smart Vault connects documents to assets, extracts
information for user confirmation, identifies missing documents, alerts users about expiry, answers questions from
saved records, and supports controlled emergency access with a waiting period and audit trail.
A concise pitch: “Smart Vault helps families move from storing documents to managing them intelligently. It connects
every document to a real-life asset, explains what is missing, tracks what is expiring, answers questions from verified
user-confirmed records, and enables carefully controlled emergency sharing.”
Be transparent in the demo: distinguish implemented features from planned features, mock AI from real Gemini
extraction, demo nominee switching from real nominee authentication, and extraction from official document
verification.

26. Key Takeaway
Smart Vault is a document autopilot, not simply a digital locker. Its core value is the complete workflow: connect
assets and documents, extract and confirm information, detect gaps, track expiry, answer questions, and securely
share selected information during emergencies. Build the P0 workflow end-to-end first, then add nominee controls and
polish. Security claims must match the implementation.
